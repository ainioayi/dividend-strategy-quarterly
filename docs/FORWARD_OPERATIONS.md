# 公开数据发布与检查

正常运行由 `.github/workflows/monthly-forward.yml` 调度：工作日北京时间
18:30 至 22:30 每小时尝试一次。交易日历与收盘边界仍控制信号和执行，
模拟账本只追加，不连接券商。

## 发布门禁

`forward_performance.py` 先校验五策略冻结合同，再对每套账户独立取最新持仓。
合并行情查询可以去重，但不能只刷新合并账本的最后一个账户。

发布前统一检查：

- 五套账户的身份、规则指纹、信号与执行先后顺序、重复事件和累计交易。
- 已发布账本必须是当前账本的完整前缀，禁止删改过去事件。
- 510300 行情日期必须与 BaoStock 核验交易日历一致；五策略使用同一时间轴。
- 每只证券在实际持仓期间的所有日期都应有价格，不能只看最新一天。
- 行情、分红、整个市场快照及公开输出指纹一致，现金加持仓市值等于总资产。
- 缺少已结束月份的信号、逾期未执行或最近账本动作失败时停止发布。

股票缺价时只查询缺失日期的 BaoStock `tradestatus`。仅明确为 `0` 的日期可
按停牌处理，沿用此前价格并展示价格日期及停牌提示；接口异常或不能确认时停止发布。
当前停牌核验仅支持沪深 A 股，ETF 和北交所缺价时保守停止，不猜测停牌。

`data_quality` 是每日检查状态，`health` 是最近一次月度账本动作的状态。
两者日期不同是正常的，例如 9 月 7 日的每日检查和 9 月 1 日的模拟执行。

每日任务在提交前再次离线复算；GitHub Pages 在上传站点前也执行相同检查。
因此文件可解析或任务成功并不足以代表上线，部署后还应核对页面数据日期和业绩指纹。

## 本地命令

仅复核当前发布文件，不联网、不写数据：

```powershell
python scripts/forward_performance.py --verify-only
```

页面字段或观察计划升级后，仅用现有行情重建业绩，不写账本：

```powershell
python scripts/forward_performance.py --offline
```

联网更新必须显式传入北京时间最新已收盘日期；截止日不能倒退。
冻结历史回测、正式前向账本和当前输入不会被离线重建覆盖。

## 历史净值更正

默认禁止已公开日期的基准或五策略净值发生变化。确认是数据或程序错误后，
可以显式传 `--correction-reason '具体错误及更正原因'`，结合正常更新或离线重建。
公开 `audit.history_corrections` 会永久保留修复原因、旧业绩指纹、旧新市场指纹和
逐日期、逐策略的前后净值；页面显示修复次数及最近原因，原发布文件保存在 Git 历史。
日常自动任务不传此参数，遇到意外历史漂移会失败并沿用已有告警流程。

2026-09-07 首次使用该流程修复“合并五账本后只刷新最后一账户持仓”：
旧股票价格停在 2026-09-01，已按原始交易账本和不复权价格重算
2026-09-02 至 2026-09-04 的历史估值，并追加 2026-09-07。
这是公开模拟业绩的数据修复，不改变冻结 V1 参数或历史回测，不改交易事件。
